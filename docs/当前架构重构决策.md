# 当前架构重构决策

- 十个地图，每个1000人数上限，总共对应最终10000人的检测目标
- 地图不分片，每张地图对应一个 `map_server` 进程。
- `map_server` 统一处理玩家进入、退出、移动、传送、nearby 和地图消息。地图消息按 `120ms` 定时批量投递给 Role，不设置满批条数，也不增加广播进程。
- 不再设置 `map_router`；Role 直接保存并调用对应 `map_server` PID。
- 玩家进入地图后，`role_server` 保存地图进程 PID，后续请求直接转发；地图消息转发后，客户端结果表示“已发送”。
- 当前阶段不处理地图进程重启后 PID 变化的问题。
- 地图状态由 `map_server` 进程 State 独占维护，不使用共享地图 ETS、地图频道或 nearby Worker。
- 地图消息批次按定时刷批时的当前成员投递；本阶段不定义加入、退出与待发批次之间的严格边界。
- AOI 使用角色所在分片及周围八个分片。加入、退出、`DOWN`、跨分片移动和传送只广播
  九宫格关系的 `enter/leave` 变化，不广播具体移动或坐标；`move` 处理方向边缘三格，
  `teleport` 计算新旧九宫格差集。
